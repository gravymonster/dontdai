# CURRENT_ARCHITECTURE.md

As-built architecture of upstream **Anarlog** at commit `08aad83`. Read-only analysis; nothing modified. Paths are upstream-relative.

This document describes what exists today. Classification (KEEP / REFACTOR / REPLACE / DELETE) and the reasoning behind each decision live in `REFACTOR_PLAN.md`; data movement is in `DATA_FLOW_MAP.md`; endpoints in `NETWORK_DEPENDENCY_MAP.md`.

## 1. Monorepo layout

Three build systems overlap: **pnpm workspaces** (`pnpm-workspace.yaml` → `apps/*`, `packages/*`, `plugins/*`, `e2e/*`), a **Cargo workspace** (`Cargo.toml` → `apps/api`, `apps/cli`, `apps/desktop/src-tauri`, `crates/*`, `legacy/*`, `plugins/*`), and **Turborepo** (`turbo.json`), plus a Taskfile and an orphaned `go.mod`.

## 3. Tauri security surface

`apps/desktop/src-tauri/tauri.conf.json`:
- `withGlobalTauri: true` → `window.__TAURI__` exposed to page scripts.
- `macOSPrivateApi: true`.
- `assetProtocol.scope: ["**/*", "$APPDATA/**"]` — the asset protocol can serve **any file on disk** via `convertFileSrc()`.
- **No `csp` key anywhere in the repo, and no CSP `<meta>` in `index.html`** → the webview gets no script/connect/frame restrictions.

`apps/desktop/src-tauri/capabilities/default.json` — one capability, `"windows": ["*"]`, applied to every webview window (main, composer, notes, floating bar, live caption, devtools panel). Security-relevant grants:

| Permission | What the renderer can do |
|---|---|
| `db:default` | `execute(sql, params)` — arbitrary SQL over the whole DB; no allow-list, no read-only mode. |
| `store2:default` | `get_secret`/`set_secret` — read/write OS keychain; only the `e2ee:` account prefix is fenced from the renderer. Provider API keys (`ai-provider-api-keys`) are renderer-readable. |
| `auth:default` | `get_item`/`set_item` — full Supabase session incl. access + refresh tokens. |
| `fs2:default` | `read_text_file`/`write_text_file`/`remove`. `write_text_file` is a free function that **bypasses** the vault-base `validate_path` its siblings use. |
| `settings:default` | `set_vault_base` relocates the fs2 sandbox root; `save` writes the settings doc that includes the `hooks` key. |
| `hooks:default` | `run_event_hooks` — spawns configured OS processes. |
| `js:default` | `eval(code)` in an embedded QuickJS VM in the Rust process; no timeout. |
| `opener2:default` | `open_url`/`open_path`/`reveal_item_in_dir` — no scope, no extension filter. |
| `shell:allow-open` | upstream shell open. |
| `http:default` (allow `https://**`, `http://**`, `http://*.*.*.*:*/**`, `http://localhost:*/**`) | arbitrary outbound HTTP; compiled with the `unsafe-headers` feature (renderer can set Cookie/Origin/Host). |
| `fs-sync:default` | 28 commands incl. `audio_import(session_id, source_path)` (copies an arbitrary absolute path into the vault) and `attachment_read → Vec<u8>`. |
| `git:default` | full git driver (init/add/commit/remote/fetch/push/pull). |
| `local-api:default` | enables a loopback HTTP server exposing meetings/transcripts; creates API keys/webhooks. |
| `detect:default` | Accessibility-API reads/writes of other apps' windows/chat. |

**Correctly narrowed (good):** `screen:default = []`, `mcp = []`, `notify = []`, `dock = []`; `sidecar2`/`mcp` register no JS commands; `clipboard-manager` is write-only.
**Outside the ACL entirely:** the ~14 app-level commands registered on `builder.invoke_handler(...)` are not covered by Tauri's capability system, including `get_env(key) → String`, which returns any environment variable to the webview unfiltered.

**Entitlements** (`Entitlements.plist`): `audio-input`, `calendars`, `addressbook`, `allow-jit`, **`allow-unsigned-executable-memory`** (disables W^X hardening; the weakest relaxation). **No `app-sandbox` key** → hardened-runtime but not sandboxed. `Info.plist` requests Microphone, **AudioCapture** (system audio), Contacts, **full** Calendar, **full** Reminders, and **Local Network**.

**Plugins registered** (`apps/desktop/src-tauri/src/lib.rs`): ~55, including upstream `opener/dialog/shell/http/os/process/store/updater/deep-link/single-instance/clipboard-manager/autostart/notification/sentry/prevent-default`. Conditional: **`relay` only under `debug_assertions` or `feature=devtools`**; `prevent-default` only in release non-devtools; `importer` macOS-only.

## 4. Plugin command surface (the IPC seam)

The renderer reaches Rust through generated `commands` objects (`invoke("plugin:<name>|<cmd>", args)`). Three representative surfaces:

- **`plugins/db`** — `execute`, `execute_transaction`, `execute_proxy`, `subscribe(Channel)`. The Rust side does **no statement inspection**; `execute_transaction` binds with `sqlx::AssertSqlSafe`. 53 frontend files hand-write SQL against the schema. Answer to "can the webview read transcripts/tokens directly?": **yes, completely** — raw SQL plus typed helpers.
- **`plugins/store2`** — `get_secret`/`set_secret`/`delete_secret` via `SecretCaller::Renderer`; only accounts prefixed `e2ee:` are blocked from the renderer. AI provider keys under `ai-provider-api-keys` are readable and are passed back down as plaintext `api_key` fields in capture params.
- **`plugins/transcription`** — `start_capture(CaptureParams{...api_key...})`, `stop_capture`, `get_capture_snapshot`, plus event streams. Live **transcript text streams into the renderer** as `CaptureDataEvent`; raw PCM does not (only amplitude ints), but the recorded file is reachable via `asset://` (`convertFileSrc`).

Sharp edges: **`plugins/js`** (`eval` in QuickJS), **`plugins/hooks`** (`run_event_hooks` → `tokio::process::Command`), and **`plugins/relay`** (dev/devtools only: `127.0.0.1:1423` WebSocket, `allow_origin(Any)`, unauthenticated, turns each message into `webview.eval("__TAURI_INTERNALS__.invoke(...)")` — a full remote-control channel; note the **staging channel is built with `--features devtools`**).

## 5. The trust boundary today

**It sits at the OS, not at the IPC.** The webview is treated as fully trusted: one capability for all windows, arbitrary SQL as a first-class API, no CSP, asset scope `**/*`, secrets and auth tokens flowing into JS by design, and app-level commands outside the ACL. The two places that *do* have a real renderer/native split are **E2EE recovery keys** (fenced behind `SecretCaller::Native`, unit-tested) and **schema ownership** (Rust owns migrations). Two facts keep it from being catastrophic in practice: every window loads `WebviewUrl::App` (no external origin is ever loaded into a privileged webview; zero `WebviewUrl::External`, zero `<iframe>`), and navigation only rewrites path+query on the same origin. Even so, any script execution in the renderer (XSS via rendered shared-note content, a malicious markdown import, or a compromised npm dependency) inherits the full grant set above.

## 7. Frontend data access

The React app reads and writes SQL directly, through a Drizzle sqlite-proxy:

```
React component
  └─ useLiveQuery / db (drizzle)            apps/desktop/src/db/index.ts
       └─ tauriLiveQueryClient {execute, executeProxy, subscribe}   packages/db-tauri
            └─ invoke("plugin:db|execute" | "execute_proxy" | "subscribe")
```

`packages/db-runtime` is pure type contracts (the seam that lets mobile swap in `expo-sqlite`); `packages/db` is Drizzle over `drizzle-orm/sqlite-proxy` with a 684-line schema mirror. Both raw-SQL template literals (dominant — 53 files) and Drizzle (minority) coexist. Writes go through an app-local `write-queue` + `retry` + `cloudsync-activity` layer. Live queries use a `tauri::ipc::Channel<QueryEvent>`. Window/tab state is Zustand, persisted via app-level commands.

## 8. Audio → STT → LLM pipeline (as-built)

Full traces with line citations are in `DATA_FLOW_MAP.md`. In summary:

- **Capture:** `cpal` microphone (downmixed to mono) + platform system-audio (macOS Core Audio **process tap** into a private aggregate device `anarlog-audio-tap`, requiring the `kTCCServiceAudioCapture` "System Audio Recording" permission; PipeWire/Pulse on Linux; WASAPI loopback on Windows). Everything resampled to **16 kHz mono**.
- **DSP:** DTLN-AEC (two ONNX models) with GCC-PHAT reference alignment, a residual echo canceller, and WebRTC-derived VAD masking on the mic track. `agc`, `segmentation`, and loudness normalization exist but are **unreferenced dead code**.
- **Orchestration:** `crates/listener-core` (a ractor actor system) fans each `CaptureFrame` to (a) the disk recorder and (b) the STT listener as 16 kHz s16le PCM. `listener2-core` handles batch/post-hoc file transcription.
- **On disk:** live `audio.wav` (32-bit float, ch0=mic, ch1=speaker), transcoded to `audio.mp3` on stop (WAV then deleted). Debug/`LISTENER_DEBUG` builds additionally leave un-cleaned `audio_mic.wav`/`audio_spk.wav`.
- **STT:** local (Soniqo/Parakeet, Apple SpeechAnalyzer) bypasses the network; cloud streams 16 kHz PCM over WebSocket to the configured provider — for `provider=anarlog`, to `wss://api.anarlog.so/stt/listen`, relayed to Deepgram/Soniox/etc. on Anarlog's keys. `whisper.cpp` local STT is present but **compiled out** (unset `whisper-cpp` feature).
- **LLM:** local via LM Studio/Ollama/Apple Foundation Models; cloud via BYO-key providers **or** the `anarlog/Auto` default (OpenRouter → Claude Sonnet through `api.anarlog.so/llm`). Summaries are rendered from Jinja templates (`crates/template-app`) with the full transcript + participants + notes as input, and stored in `session_documents`.
- **Diarization:** on-device via Soniqo `ParakeetBatch`, or provider-side in cloud mode; `pyannote-local` exists but is dormant. **No text-embedding / vector / RAG pipeline exists** — "semantic" search is Tantivy BM25 plus handing text to the LLM.

## 9. Storage (as-built)

Full detail in `DATA_FLOW_MAP.md`. Canonical store is **SQLite via `sqlx`** at `~/Library/Application Support/anarlog/app.db` (WAL, foreign keys on), with the closed **SQLite Cloud `cloudsync`** extension loaded into every connection. Core tables: `sessions`, `session_documents` (notes/summaries/template output as ProseMirror JSON), `transcripts` (`words_json`), `session_participants`, `humans`, `organizations`, `action_items`, `session_attachments`, `calendars`, `events`, `templates`, `app_settings`, plus `e2ee_records`/`e2ee_local_state`, `api_keys`/`webhook_endpoints`, `shared_session_cache`.

**Nothing is encrypted at rest.** `app.db`, audio files, the Tantivy `search_index/` (a second plaintext copy of note+transcript text with `STORED` fields), `settings.json`, `store.json`, and — on macOS — `auth.json` (Supabase tokens) are all plaintext. Secrets that *do* use the keychain: provider API keys and the E2EE recovery key (and, on Linux, the auth session). Deletion is **tombstone-only** (`deleted_at`) with **no purge/vacuum** of domain rows; the session folder (audio + attachments) is removed but rows persist indefinitely. Audio retention defaults to **`forever`**; `cloud_sync_enabled` defaults to **`true`** (though E2EE and gated on recovery-key setup).

## 10. Authentication & vendor cloud (as-built)

Full detail in `NETWORK_DEPENDENCY_MAP.md`. Sign-in is a **browser handoff**: the desktop opens `anarlog.so/auth?flow=desktop` in the system browser; the web app performs Supabase OAuth (**Google or GitHub**) or magic link, then returns `<scheme>://auth/callback?access_token=…&refresh_token=…` (tokens in a URL query string). Entitlements ride in the Supabase JWT (`hyprnote_pro`/`hyprnote_lite`, plus `trialing`). Sign-in is **not required** — local STT + local LLM work fully offline — but onboarding auto-starts a trial, which flips STT/LLM to cloud. Third-party calendar/ticket OAuth is brokered by **Nango**, with those tokens held **server-side** in the vendor cloud; Apple Calendar (EventKit) is fully on-device. Telemetry (PostHog) and crash reporting (Sentry, incl. 10% session replay) are compiled in and default-on; the updater polls `desktop2.hyprnote.com` on launch and every 30 minutes.

## 11. Structural observations relevant to the refactor

1. `build.minify: false` in release; unminified bundles ship.
2. A **closed-source `cloudsync.dylib`** is loaded as a SQLite extension into the process holding all user data.
3. `plugins/js` = a QuickJS `eval` endpoint granted to the webview by default.
4. The dev **relay** (unauthenticated full-IPC WebSocket) is compiled into `devtools`/staging builds.
5. Bundle IDs (`com.hyprnote.*`), keychain (`com.anarlog.*`), updater (`desktop2.hyprnote.com`), and deep-link schemes (`hypr`/`char`/`anarlog`) span three naming eras.
6. `examples/plugins/` + `packages/plugin-sdk` are dead remnants of a third-party-JS-into-main-renderer loader that no longer exists.
7. `go.mod` with zero Go files; `memory`/`segmentation`/`embedding` and several `api-*` crates are orphaned.
8. Model downloads verify by **CRC32** or not at all; the updater is properly minisign-signed.
9. 175 crates + ~50 plugins is a large surface for a single self-hoster to audit; adding one command touches four files across two languages plus a JSON capability file.
